# Fitting complete English passages

**Current state: static proof, emulator test pending.** The first 24-glyph limit was a *line* observation, not a proven limit on an entire text run or message. The PC-98 demo showed the 25th glyph wrap to the next line. In the extracted original corpus, text commands `B0` and `B3` occur frequently. The [XLVNS Kizuato interpreter](https://github.com/catmirrors/xlvns/blob/master/kizuato.c) treats `B0` as a new line and `B3` as wait for the player, then clear the page. Its [text renderer](https://github.com/catmirrors/xlvns/blob/master/LvnsText.c) has a 16-row text buffer. These are supporting source-code observations from a later port, not direct proof of the original PC-98 engine's behavior. A static pass over the supplied original messages, assuming 24 columns and `B0`/`B3` semantics, found a maximum of 13 occupied rows per original page.

`python tools/build_live_patch.py --paginate` is an **experimental** way to keep complete PLaMo wording: it distributes every word over the original text runs, inserts `B0` line breaks at 24 glyphs, and inserts `B3` page advances before the inferred 13-row budget is exceeded. The builder verifies that the ordered English words are unchanged, retains every original command in order, rebuilds all scene events byte-identically, and creates a new HDI copy. It never writes to the source HDI. A disposable first probe from the live cache inserted 72 complete drafts, including 492 added line commands and 48 added page commands. The PAK read back correctly, but **the inserted page behavior has not yet been observed in the PC-98 emulator**. Additional page advances change reading pace and savepoint timing; they must be checked during gameplay.

Whole-message reflow also changes which words appear before an original command between text runs. `tools/audit_timing.py` checks this risk without copying game text into Git. On the 2,802-message full-cache middle-dot preview, it flagged 2,554 messages with non-newline commands between text runs; 2,552 had `B2`. The related XLVNS interpreter implements `B2` as wait-for-key. The PC-98 engine's exact behavior still needs checking, but command-order preservation alone does **not** establish pacing or effect alignment. Translate and format these messages by pause/effect segment, or review each boundary, before a release build.

The first probe left many drafts in Japanese because the original font mapping has no verified apostrophe glyph. `--apostrophe-dot` is an **explicit typography probe** that displays unresolved apostrophes using the existing native middle-dot glyph. It never removes letters or words, but its punctuation is not suitable for a final patch. With both `--paginate --apostrophe-dot`, a second live-cache snapshot inserted 217 complete drafts; the rest were still translating or failed a stated constraint. That test also passed archive rebuild and HDI readback, but it has not been played. The user asked for fully readable English, so this middle-dot mode is only a bridge while a proper apostrophe/font solution is researched.

`KNJ_ALL.KCD` is inside the original `MAX2_SYS.PAK` (130,342 bytes), and its file begins with a 24-bit glyph count of 2,083 followed by 24-bit glyph offsets. Shrinking bitmap strokes inside the existing 24-column grid would not increase the number of characters per row: the cursor advances one cell per glyph in the related XLVNS renderer. A true compact or proportional font requires a native engine layout change, or a different script pagination strategy. No native engine change has been made.

Before using pagination as the normal build mode:

1. Boot a disposable paginated HDI and advance through an opening passage that contains an inserted `B3`, checking that the next page displays its remaining English words and reaches the next event.
2. Check an option screen separately. The current paginator excludes choice prompts/options from added page commands; overlong options stay Japanese for manual shortening. Selection highlighting and cursor placement need observation before allowing extra choice lines.
3. Confirm text history/savepoint behavior after inserted pages, including loading a bookmark on the next scene. Record the emulator build/settings and screenshots only under ignored `build/`.
4. Add a proper English apostrophe glyph or a reviewed spelling convention, then rerun a no-truncation build. Do not silently replace punctuation in release output.
